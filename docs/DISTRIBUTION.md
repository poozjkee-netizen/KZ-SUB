# Раздача плагина пользователям (.zxp)

Чтобы человек поставил плагин **без режима разработчика**, панель нужно
упаковать в подписанный `.zxp`. Ниже — как ТЫ собираешь `.zxp` и как КЛИЕНТ его
ставит.

---

## Часть 1. Сборка `.zxp` (делаешь ты, один раз на версию)

### 1. Получить инструмент ZXPSignCmd
Это официальная утилита Adobe для подписи расширений. Варианты, как достать:

- **Проще всего:** скачай готовый бинарник `ZXPSignCmd` для macOS из репозитория
  Adobe CEP-Resources или зеркал (поиск: «ZXPSignCmd macOS download»). Положи,
  например, в `~/bin/ZXPSignCmd`.
- Сними «карантин» macOS, иначе система не даст запустить:
  ```bash
  xattr -d com.apple.quarantine ~/bin/ZXPSignCmd 2>/dev/null || true
  chmod +x ~/bin/ZXPSignCmd
  ```

### 2. Собрать подписанный `.zxp`
```bash
cd ~/kz-sub
ZXPSIGNCMD=~/bin/ZXPSignCmd bash scripts/build-zxp.sh
```
Скрипт:
1. создаёт самоподписанный сертификат `dist/kzsub-cert.p12` (один раз);
2. подписывает папку `plugin/` в `dist/KZ-SUB.zxp` с временной меткой.

Результат: **`dist/KZ-SUB.zxp`** — это и есть файл, который ты раздаёшь.

> Сертификат самоподписанный — этого достаточно для установки через ZXP-инсталлер.
> Для публикации на **Adobe Exchange** позже понадобится их процедура ревью
> (самоподписи хватает для прямой раздачи клиентам).

### 3. Когда нужен новый `.zxp` (важно!)

| Что изменил | Нужен новый `.zxp`? |
|---|---|
| Панель: `index.html`, `css`, `js`, `jsx`, пресет, иконки | **Да** — пересобрать и раздать |
| Бэкенд: качество/нарезка/пунктуация, квоты, ключи, device-binding на сервере, новые языки на сервере | **Нет** — только `fly deploy`, пользователи получают сразу |

Правило: `.zxp` = «морда» плагина на компьютере пользователя. Всё, что считается
на сервере, обновляется деплоем шлюза и не требует переустановки у клиентов.

### 4. Перевыпуск при обновлениях панели
1. Подними версию в `plugin/CSXS/manifest.xml` (`ExtensionBundleVersion` **и**
   `Extension Version`) — иначе установщик не распознает обновление.
2. Снова запусти `build-zxp.sh` (тем же сертификатом — не удаляй
   `dist/kzsub-cert.p12`, иначе для Premiere это будет «другой» плагин).
3. Раздай новый файл пользователям (ставится поверх старого).

## Часть 2. Инструкция для клиента (даёшь вместе с файлом)

**Что нужно:** файл `KZ-SUB.zxp` и ключ активации (выдаёшь ты).

> Один и тот же `.zxp` ставится и на **macOS**, и на **Windows** — файл
> кроссплатформенный, переподписывать под Windows не нужно.

### Установка (macOS/Windows)
1. Скачать бесплатный установщик расширений:
   **ZXP/UXP Installer** (aescripts) или **Anastasiy's Extension Manager**.
2. Перетащить в него файл `KZ-SUB.zxp` → **Install**. Он сам разложит панель и
   разрешит самоподписанное расширение.
3. Полностью перезапустить Premiere Pro.
4. **Window → Extensions → KZ-SUB**.
5. Открыть ⚙, ввести **ключ активации**, нажать «Тексеру» — панель готова.

### Использование
- Открыть секвенцию с казахской речью → кнопка **«СУБТИТР ЖАСАУ»**.
- Через несколько секунд субтитры появятся на новой дорожке субтитров.

## Выдача ключей клиентам
Ключ активации = запись в `KZSUB_API_KEYS` на шлюзе (Fly). Добавить нового
клиента:
```bash
cd ~/kz-sub/backend
fly secrets set KZSUB_API_KEYS="client-1-xxxx:pro,client-2-yyyy:pro,trial-zzz:free"
```
(перечисляешь ВСЕ активные ключи через запятую; `:free` — с лимитом минут,
`:pro` — без лимита на уровне шлюза). Каждый ключ работает максимум на
`KZSUB_MAX_DEVICES_PER_KEY` устройствах (по умолчанию 2) — защита от передачи
ключа посторонним.
