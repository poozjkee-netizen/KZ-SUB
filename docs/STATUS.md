## 1. Что за продукт (в одну строку)

Плагин для Adobe Premiere Pro, который распознаёт **казахскую речь** и
кладёт субтитры на таймлайн. Premiere «из коробки» казахский не умеет — это
и есть боль, которую мы решаем. Ядро ценности — **качество ASR**, а не код панели.

**Стадия: готов к коммерческому запуску.** Продукт работает end-to-end на
проде; система лицензий и ручные продажи через Kaspi настроены.

## 2. Три деплой-единицы — статус

| Единица | Где | Статус | Как катится |
|---|---|---|---|
| **Панель** (`plugin/` → `.zxp`) | у пользователя | ✅ v1.2.0, готова к сборке | пересобрать `.zxp`, раздать |
| **Шлюз** (`backend/app/` → Fly) | `kzsub-gateway` | ✅ в проде, всегда поднят | `fly deploy` |
| **GPU-воркер** (`backend/serverless/` → Runpod) | Serverless GPU | ✅ в проде, ~20–30 с/прогон | пересобрать образ → сменить у эндпоинта |

Поток: Панель → (multipart аудио) → Шлюз → (Runpod API) → GPU-воркер (Whisper
large-v3) → сегменты → Шлюз → `.srt` → Панель кладёт на дорожку.

---

## 3. Что РАБОТАЕТ в проде (подтверждено)

- **Транскрибация казахского** — Whisper large-v3 на Runpod, прогон 20–30 с.
- **Надёжность GPU (ADR-13):** лёгкий образ без вшитых весов, без Network
  Volume, Data Centers = Any + все 24GB-карты, FlashBoot ON → «High Supply».
- **Шлюз всегда доступен** — `min_machines_running=1`, один воркер uvicorn
  (убрана гонка SQLite при засеве ключей).
- **Система лицензий** на SQLite (том Fly): проверка ключа/статуса/срока/минут
  на каждом запросе; заголовок `X-Minutes-Remaining`.
- **Ручная выдача ключей** через CLI (`python -m app.licenses create --plan …`).
- **БД чистая** — оставлена одна developer-лицензия, тестовые ключи снесены.

## 4. Что РЕАЛИЗОВАНО в коде

### Панель (v1.2.0)
- Гейт активации при первом запуске: без валидного ключа в основной UI не пускает.
- Кнопка «Проверить» валидирует **сам ключ** на сервере (не только доступность),
  показывает статус/остаток минут или причину отказа.
- Прогресс обработки по этапам с процентами (подготовка → экспорт → загрузка →
  распознавание → создание → импорт).
- Полная локализация интерфейса: единый словарь `plugin/js/i18n.js` (ru/kk),
  выбор языка в Настройках сохраняется; `host.jsx` отдаёт коды ошибок (текст в словаре).
- Язык **субтитров** вынесен в шапку (казахский; «скоро» кыргызский/узбекский),
  язык **интерфейса** — в настройках. «powered by danik np» в футере.
- Анти-шаринг: отпечаток устройства `X-Device-Id`, лимит устройств на ключ.

### Шлюз (`backend/app/`)
- Два режима из одного `main.py`: локальный Whisper (dev) / прокси в Runpod (прод).
- `POST /transcribe` — проверка лицензии до и после чтения аудио, списание минут.
- `GET /license` — read-only статус ключа (для «Проверить» и будущего кабинета).
- `GET /health`.
- Конвейер: `transcribe` → `segmentation` (word-караоке / phrase) → `style` → `srt`.
- Лицензии (`licenses.py`): типы developer/trial/subscription/minute_pack/lifetime,
  статусы active/expired/exhausted/suspended/revoked; CLI create/list/plans/topup/
  renew/revoke/suspend/activate/delete/purge-revoked.
- Каталог тарифов (`plans.py`) — единый источник, шов `create_from_plan` под будущий вебхук.

### Воркер (`serverless/`)
- Принимает только доверенный внутренний ключ; транскрибирует + нарезает + стилизует.

### Тесты
- Dep-free: `test_srt`, `test_licenses`, `test_segmentation`, `test_style`, `test_devices`.
- Интеграционный: `test_api` (HTTP-контракт с замоканной моделью).

## 6. Что ЗАГЛУШКА / ещё НЕ сделано

| Область | Сейчас | Нужно для масштаба |
|---|---|---|
| **Оплата** | вручную (Kaspi перевод → CLI выдаёт ключ) | вебхук Kaspi/Stripe → авто `create_from_plan` |

| **Дистрибуция** | прямая раздача `.zxp` | Adobe Exchange, лендинг, инфлюенсеры |

## 7. Открытые развилки (что решить перед планом)

1. **Куда вкладывать силы первым:** рост качества ASR (моут, удержание) vs
   автоматизация продаж (снять ручной труд) vs каналы привлечения (лендинг/инфлюенсеры)?
2. **Проверен ли `.zxp` 1.2.0 в живом Premiere?** Гейт активации, «Проверить»,
   переключение языка, прогресс — прогнать чек-лист до первой продажи.
3. **Пробная продажа:** прогнать полный цикл Kaspi → `create --plan` → выдача,
   убедиться, что клиент получает рабочий ключ и инструкцию.
4. **Сбор датасета:** начать ли (с согласия, анонимно) копить казахскую речь под
   fine-tune — это то, что конкурент не скопирует быстро.
5. **Метрики:** что меряем с первого дня (GPU-утилизация, минут/юзер, WER, конверсия Free→Pro).

## 8. Кандидаты в план действий

- **A. Запуск и первая продажа.** Проверить `.zxp` в Premiere → тестовая
  Kaspi-продажа → выдать ключ реальному пользователю. Низкий риск, быстрый сигнал рынка.
- **B. Качество казахского ASR (ядро ценности).** Постобработка (пунктуация,
  нормализация чисел/сокращений), пользовательский словарь терминов, замер WER на
  реальных роликах. Строит моут, растит удержание.
- **C. Автоматизация выдачи.** Telegram-бот или вебхук оплаты → `create_from_plan`.
  Имеет смысл, когда пойдёт поток (сейчас ручной путь дешевле).
- **D. Каналы привлечения.** Лендинг с демо до/после на казахском, работа с
  казахоязычными блогерами (они же ЦА и канал).

**Рекомендация:** A (быстро, разблокирует деньги и обратную связь) → затем
B (это то, что реально держит продукт). C и D — по мере роста потока.
