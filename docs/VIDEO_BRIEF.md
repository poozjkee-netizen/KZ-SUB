# NP Brief — приложение для Mac: ссылка на ролик → разбор и свой сценарий

Отдельная программа (не часть NP SUB): вставляешь ссылку на ролик — YouTube,
Instagram, TikTok — и получаешь расшифровку, разбор «почему это смотрят» и
готовый черновик **своего** сценария по той же схеме. Ролик может быть на любом
языке, **разбор всегда на русском**.

**Всё считается на твоём маке.** Ни ключей, ни облака, ни отдельного сервера:
модель `.gguf` читается прямо в процессе программы (см. [ADR-17](DECISIONS.md)).

Код — в [`tools/videobrief/`](../tools/videobrief/). Ни Fly, ни Runpod, ни панель
не затронуты.

## Что нужно на маке

| Что | Зачем | Ставится |
|---|---|---|
| `yt-dlp` | скачать метаданные, субтитры и аудио | установщиком |
| `faster-whisper` | распознать речь, если субтитров нет | установщиком |
| `llama-cpp-python` | прочитать модель `.gguf` и сделать разбор | установщиком |
| файл модели `.gguf` | собственно разбор | у тебя уже есть либо кладёшь в `~/Models` |

Модель — любая инструкт-версия (в имени `-it`, `instruct`, `chat`). Программа
сама находит файлы в `~/Models`, папке Cotypist/NPAutocomplete, у LM Studio и в
загрузках; из найденных берёт инструкт-версию покрупнее. Базовые модели не
годятся: они продолжают текст, а не выполняют указания.

## Установка (один раз)

В Терминале, из папки репозитория:

```bash
bash scripts/install-np-brief-mac.sh
```

Скрипт создаёт отдельное окружение Python, ставит три пакета выше, копирует
программу в `~/Library/Application Support/NP Brief` и собирает
**`~/Applications/NP Brief.app`**. Больше Терминал не нужен. Повторный запуск
скрипта = обновление.

`llama-cpp-python` может собираться несколько минут — это разово.

## Как пользоваться

1. Открой **NP Brief** двойным кликом (лежит в `~/Applications`).
2. Вставь ссылку → **Разобрать**.
3. Разбор появится в окне: вкладки «Разбор», «Чистый текст», «С тайм-кодами»,
   кнопки «Скопировать» и «Показать в Finder».

В настройках (**⚙︎**) задаются: файл модели (кнопка показывает найденные на
маке), аудитория своей версии, папка для результатов и модель распознавания.

Файлы каждого ролика — в `~/Movies/NP Brief/<ролик>/`:

| Файл | Что внутри |
|---|---|
| `brief.md` | разбор: о чём ролик, почему его смотрят, структура, каркас, свой черновик |
| `transcript.txt` | чистый текст ролика, как сказано, без тайм-кодов |
| `transcript.timed.txt` | тот же текст с тайм-кодами |
| `prompt.txt` | задание, ушедшее модели — можно поправить и прогнать снова |
| `meta.json` | метаданные ролика и чем он расшифрован |

## Как это устроено

```
ссылка → yt-dlp → [субтитры ролика]  ─┐
                  [аудио → Whisper]  ─┴→ чистка текста → модель .gguf → brief.md
```

1. **Метаданные** — один запрос yt-dlp (название, автор, длительность, просмотры).
2. **Текст.** Сначала готовые субтитры ролика — это секунды вместо минут
   распознавания. Нет субтитров или площадка их не отдала (бывает `429`) —
   скачивается аудиодорожка и распознаётся Whisper с авто-детектом языка.
3. **Чистка.** Авто-субтитры идут «бегущей строкой» с повторами — они
   схлопываются; короткие реплики склеиваются в блоки по ~12 секунд.
4. **Разбор.** Модель получает метаданные и расшифровку с тайм-кодами и отвечает
   по жёсткой структуре — одинаковой для всех роликов, чтобы их можно было
   сравнивать: о чём ролик → паспорт → почему это смотрят (хук дословно,
   удержание, петля) → структура по блокам таблицей → сценарий целиком на
   русском → каркас-формула → как сделать свою версию (3 хука, своя тема) →
   черновик своего сценария → чего не копировать.

**Длинный ролик** не влезает в окно модели, поэтому расшифровка сначала
сжимается по частям (каждая — со своими тайм-кодами и дословными хуками), а
разбор идёт по конспекту. На диск при этом пишется полный текст.

**Модель остаётся в памяти** между роликами: первый разбор ждёт загрузку файла,
следующие начинаются сразу.

## Модули

| Файл | Ответственность |
|---|---|
| `settings.py` | единственный конфиг: файл настроек + переменные `VIDEOBRIEF_*` |
| `media.py` | yt-dlp: метаданные, субтитры, аудио |
| `captions.py` | разбор `.vtt` / `.srt` |
| `transcript.py` | сегменты → чистый текст, тайм-коды, блоки, нарезка длинного |
| `asr.py` | faster-whisper (только CPU: видеокарту ctranslate2 не использует) |
| `llm.py` | поиск `.gguf`, загрузка модели в процесс, поток ответа |
| `prompt.py` | системный промпт разбора и промпт сжатия — ядро ценности |
| `pipeline.py` | весь прогон: текст → чистка → разбор → файлы |
| `webapp.py` + `ui.html` | окно программы |
| `cli.py` | то же из командной строки |

## Командная строка

```bash
python -m tools.videobrief "https://www.youtube.com/watch?v=..."
python -m tools.videobrief "<ссылка>" --no-analysis          # только расшифровка
python -m tools.videobrief ролик.mp4 --transcript субтитры.srt
python -m tools.videobrief.webapp                            # окно без установки
```

| Ключ | Зачем |
|---|---|
| `--model ФАЙЛ.gguf` | какой моделью разбирать |
| `--audience "..."` | под кого делаем свою версию |
| `--mode auto\|subs\|asr` | откуда брать текст |
| `--transcript ФАЙЛ` | взять готовую расшифровку (`.vtt`/`.srt`/`.txt`) |
| `--whisper`, `--lang` | модель и язык распознавания |
| `--no-analysis` | не звать модель: только расшифровка и промпт |
| `--out`, `--quiet` | папка результата, тишина в логе |

## Настройки

Хранятся в `~/Library/Application Support/NP Brief/settings.json`. Любую можно
перебить переменной окружения `VIDEOBRIEF_<ИМЯ>` — удобно для разовых прогонов.

| Ключ / переменная | По умолчанию | Смысл |
|---|---|---|
| `model_path` / `VIDEOBRIEF_MODEL_PATH` | — | файл модели; пусто = выбрать самой |
| `audience` / `VIDEOBRIEF_AUDIENCE` | русскоязычная аудитория СНГ | под кого своя версия |
| `out_dir` / `VIDEOBRIEF_OUT_DIR` | `~/Movies/NP Brief` | куда складывать разборы |
| `whisper` / `VIDEOBRIEF_WHISPER` | `large-v3` | модель распознавания |
| `ctx` / `VIDEOBRIEF_CTX` | `16384` | окно контекста модели (токенов) |
| `max_chars` / `VIDEOBRIEF_MAX_CHARS` | `16000` | порог, после которого текст сжимается по частям |
| `VIDEOBRIEF_STATE_DIR` | папка поддержки | где лежат настройки |

## Безопасность

Окно — локальный сервер на `127.0.0.1` со случайным токеном в адресе. Без токена
любой запрос получает `403`, поэтому чужая страница в браузере не может ни
запустить прогон, ни прочитать настройки. Наружу не уходит ничего: ни ссылки,
ни текст ролика — кроме самого скачивания с площадки.

## Тесты

```bash
python tools/videobrief/tests/test_transcript.py   # текст: чистка, блоки, нарезка
python tools/videobrief/tests/test_captions.py     # разбор .vtt/.srt
python tools/videobrief/tests/test_llm.py          # поиск .gguf, выбор, поток ответа
python tools/videobrief/tests/test_pipeline.py     # субтитры, промпт, отказ площадки
python tools/videobrief/tests/test_webapp.py       # окно: токен, настройки, прогон
```

Скачивание, распознавание и сама модель автотестами не покрыты — они требуют
сети и гигабайтов; проверяются вручную на одном коротком ролике.

## Частые грабли

- **«Не установлен llama-cpp-python»** — запусти установщик ещё раз; если сборка
  падает, поставь инструменты разработчика: `xcode-select --install`.
- **«Не нашёл ни одной модели .gguf»** — положи файл в `~/Models` или укажи путь
  в настройках. Файлы меньше 100 МБ не считаются моделями (это словари).
- **Модель отвечает медленно** — 12B на маке пишет длинный разбор минуты. Быстрее
  идёт модель поменьше (например `gemma-4-E4B-it`) или меньшее окно `ctx`.
- **Instagram отдаёт ошибку** — приватные аккаунты и ролики «только для
  подписчиков» не скачиваются; ссылка должна открываться без входа.
- **Текст ролика — это чужой текст.** Программа даёт разбор и каркас, а не
  разрешение копировать дословно; раздел «Чего не копировать» в `brief.md` про это.
