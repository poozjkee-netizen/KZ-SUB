# Качество казахского ASR

Статус: 🟡 Базовая модель работает · развитие
Приоритет: **P1**
Зависимости: [06-analytics](06-analytics.md) (замер WER — общий инструмент)

← [Индекс проекта (PROJECT.md)](../PROJECT.md)

## Цель

Сделать качество распознавания казахского **моутом** продукта: субтитры точнее и
чище, чем у любого «обёрточного» конкурента. По CLAUDE.md это ядро ценности —
панель копируется за неделю, хорошая модель — нет.

## Описание

Сейчас в проде Whisper `large-v3`, язык `kk`, с нарезкой и базовой стилизацией
(регистр/пунктуация) плюс постобработка на шлюзе (`app/postprocess.py`): фильтр
зацикливаний модели и пользовательский словарь правок. Инструмент замера WER/CER
готов (`app/wer.py`), но baseline на реальных роликах ещё не снят — нужны
эталонные транскрипты. Долгосрочный отрыв даёт собственный датасет
казахской речи + fine-tune. Вся серверная логика катится без переустановки
панели — предпочитаем делать здесь.

## Подзадачи

- [x] **Инструмент замера WER/CER** — `app/wer.py` (dep-free): WER, CER, разбор
      ошибок по типам (замены/вставки/удаления), парсер `.srt`, NFC-нормализация,
      CLI `python -m app.wer эталон.txt распознанное.srt`. Гейт для всех правок ниже.
- [ ] **Замер WER baseline** `large-v3` на реальных казахских роликах — нужен
      набор эталонных транскриптов (инструмент готов, данных пока нет)
- [x] **Фильтр зацикливаний Whisper** — модель на тишине печатала одно слово
      десятки раз подряд; `KZSUB_MAX_REPEATS` (по умолчанию 3)
- [x] **Пользовательский словарь** (имена, термины канала) — `KZSUB_LEXICON` /
      `KZSUB_LEXICON_PATH`, замены по границам слов с сохранением регистра,
      пустая правая часть удаляет слово
- [x] **Отсев неправдоподобно долгих реплик** — `KZSUB_MAX_CUE_DROP_SECONDS`
      (по умолчанию выключено: включать под замер WER)
- [ ] **Постобработка текста** (только для режима `phrase` — в караоке-режиме
      пунктуация всё равно снимается):
  - [ ] Восстановление пунктуации
  - [ ] Нормализация чисел, дат, сокращений
- [ ] **Подсказки модели при декодировании** (`initial_prompt`/`hotwords` в
      `transcribe.py`) — сильнее словаря, но требует пересборки GPU-образа
- [ ] **Сравнение** с Yandex SpeechKit (kk-KZ) и ISSAI Soyle — где мы лучше/хуже
- [ ] **Сбор датасета** казахской речи (с согласия пользователей, анонимно) → сервер
- [ ] **Fine-tuning** Whisper на Kazakh Speech Corpus (KSC2) + собранном датасете
- [x] Dep-free тесты: `test_wer.py`, `test_postprocess.py`

## Definition of Done

- Есть воспроизводимый замер WER до/после каждого улучшения (регресс не проходит).
- Постобработка и словарь включаемы через `config.py` (`KZSUB_*`) и покрыты тестами.
- Сформулирована и запущена стратегия датасета/fine-tune как долгосрочный отрыв.

## Заметки

- **Постобработка живёт на шлюзе, не в воркере.** Так правки катятся одним
  `fly deploy`, тогда как те же изменения внутри воркера потребовали бы
  пересборки Docker-образа и смены образа у эндпоинта Runpod.
- Порядок работы над качеством: получить `.srt` до правки → замерить WER →
  внести правку → сравнить. Без цифр улучшение недоказуемо, регресс не виден.
- Развилка STATUS §7.4: начать ли копить датасет с первого дня — да, это то, что конкурент не скопирует быстро.
- Модель не покидает инфраструктуру (серверная обработка) — часть моута.
- Постобработку держим на бэкенде: катится без новой `.zxp`.
- Замер WER пересекается с [06-analytics](06-analytics.md) (метрика удержания).
