# Автоматизация продаж и оплаты

Статус: 🔴 Не начато
Приоритет: **P2**
Зависимости: [02-licensing](02-licensing.md) (шов `create_from_plan` готов)

← [Индекс проекта (PROJECT.md)](../PROJECT.md)

## Цель

Убрать ручной труд из выдачи ключей: платёж → автоматическое создание лицензии
по тарифу и доставка ключа клиенту. Подключается, когда поток продаж вырастет и
ручной путь (Kaspi → CLI) перестанет справляться.

## Описание

Шов готов: `licenses.create_from_plan(email, plan)` (тарифы — единый источник в
`app/plans.py`). Осталось подключить провайдера оплаты/доставки, который вызовет
эту функцию после подтверждённого платежа. Пока действует ручной цикл из
[DISTRIBUTION.md](../DISTRIBUTION.md) — сознательно самый дешёвый старт для рынка KZ.

## Подзадачи

- [ ] **Вебхук оплаты** → `create_from_plan(email, plan)`:
  - [ ] Kaspi (приоритет для KZ — доминирующий способ оплаты)
  - [ ] Карты: Stripe / Paddle (Paddle как merchant of record — берёт НДС/налоги)
- [ ] **Доставка ключа** клиенту (email и/или Telegram-бот)
- [ ] **Telegram-бот выдачи** — приём оплаты/подтверждения → выдача ключа
- [ ] Идемпотентность и защита вебхука (подпись провайдера, повтор платежа не плодит ключи)
- [ ] Годовые тарифы со скидкой (улучшают cashflow и удержание)
- [ ] Промо-коды / реферальные скидки
- [ ] Продление подписки по повторному платежу (renew вместо нового ключа)

## Definition of Done

- Подтверждённый платёж автоматически создаёт корректную лицензию и доставляет ключ без ручного участия.
- Повторные/дублирующие вебхуки не создают лишних лицензий.
- Ручной путь (CLI) остаётся рабочим как фолбэк.

## Заметки

- Не автоматизируй раньше времени: при малом потоке ручной путь дешевле и надёжнее.
- Kaspi не имеет удобного публичного API — на старте возможен полу-ручной приём (QR/перевод) + бот подтверждения.
- Единый источник тарифов — `app/plans.py`; вебхук только передаёт `plan`.
