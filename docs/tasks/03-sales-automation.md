# Автоматизация продаж и оплаты

Статус: 🟡 В работе (Telegram-бот готов, полу-авто + напоминания)
Приоритет: **P2**
Зависимости: [02-licensing](02-licensing.md) (шов `create_from_plan` готов)

← [Индекс проекта (PROJECT.md)](../PROJECT.md)

## Цель

Убрать ручной труд из выдачи ключей: платёж → автоматическое создание лицензии
по тарифу и доставка ключа клиенту. Подключается, когда поток продаж вырастет и
ручной путь (Kaspi → CLI) перестанет справляться.

## Описание

Шов готов: `licenses.create_from_plan(email, plan)` (тарифы — единый источник в
`app/plans.py`). Реализован **Telegram-бот выдачи** (`app/telegram_bot.py`,
вебхук `POST /telegram/webhook` в `main.py`):

- **Demo** (3 мин) — полностью автоматически, один раз на Telegram-аккаунт
  (email лицензии хранит `tg:<id>`, повторный `/demo` не выдаёт второй ключ).
- **Standard** (60 мин/30 дней) — полу-авто: клиент жмёт «Я оплатил» после
  перевода на Kaspi → заявка с кнопками Подтвердить/Отклонить уходит
  продавцу (`KZSUB_TELEGRAM_ADMIN_IDS`) → после подтверждения бот сам создаёт
  лицензию и присылает ключ клиенту в тот же чат.

Полностью авто (без участия продавца) для Standard упирается в то же
ограничение, что и раньше: у Kaspi нет публичного API для проверки перевода —
решение о зачислении оплаты сознательно остаётся за человеком. Настройка и
запуск — в [`backend/README.md`](../../backend/README.md#telegram-бот-выдачи-ключей-apptelegram_botpy).
Ручной цикл из [DISTRIBUTION.md](../DISTRIBUTION.md) (CLI) остаётся рабочим
как фолбэк.

      подтверждение продавцом → авто-выдача Standard, `/whoami` (узнать свой ID)
- [x] Вебхук защищён секретом (`X-Telegram-Bot-Api-Secret-Token`), отключён по
      умолчанию (404 без токена)
- [x] Защита от повторной выдачи: double-confirm/двойной клик не плодит вторую лицензию

- [ ] Годовые тарифы со скидкой (улучшают cashflow и удержание)
- [ ] Промо-коды / реферальные скидки
- [ ] Продление подписки по повторному платежу (renew вместо нового ключа) — сейчас повторный `/buy` создаст новую заявку, не продление существующей.
      Напоминание из `notify.py` уже приводит клиента к `/buy` в нужный момент — осталось сделать сам renew
- [ ] Несколько параллельных админов: сейчас конкурирующее подтверждение защищено (переиспользуется существующая лицензия), но нет блокировки одновременного показа заявки — приемлемо при одном активном продавце

## Definition of Done

- Подтверждённый платёж создаёт корректную лицензию и доставляет ключ без ручного участия в выдаче (человек нужен только для подтверждения факта оплаты).
- Повторные/дублирующие подтверждения не создают лишних лицензий.
- Ручной путь (CLI) остаётся рабочим как фолбэк.

## Заметки

- Не автоматизируй раньше времени: при малом потоке ручной путь дешевле и надёжнее — бот именно поэтому полу-авто, а не полностью.
- Единый источник тарифов — `app/plans.py`; бот только передаёт `plan` в `create_from_plan`.
- Токен бота — секрет, только через `fly secrets set`, никогда в код/git/чат.
- Бот пока русскоязычный (не билингвальный ru/kk, в отличие от панели) — упрощение для MVP; расширить при необходимости.
- `.zxp`-файл бот пока не рассылает (только ключ) — раздача плагина остаётся отдельным шагом ([01-commercial-launch](01-commercial-launch.md)/[08-marketing](08-marketing.md)).
