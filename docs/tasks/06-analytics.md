## Цель

Видеть, что происходит с продуктом и экономикой с первого дня: рычаги маржи,
качество, конверсию и удержание. Без метрик нельзя калибровать лимиты, цены и
приоритеты.

## Описание

Метрики перечислены в [MONETIZATION.md](../MONETIZATION.md) («Метрики, за
которыми следить»). Базовый сбор есть: `app/events.py` пишет строку на каждый
прогон `/transcribe` в SQLite на том же томе, что и лицензии, а CLI печатает
срез за период. Сознательно начали с минимума — таблица и две команды вместо
дашборда, потому что решения о цене и лимитах принимаются раз в неделю, а не
в реальном времени.

## Подзадачи

- [x] **Минимальный набор событий** — `app/events.py`: время, тариф, режим
      (proxy/local), статус, причина отказа, длительность аудио, время
      обработки, число реплик. Пишется из `/transcribe` снаружи обработки,
      поэтому в статистику попадают и отказы, и падения
- [x] **Срез за период** — `python -m app.events summary --days 7`:
      прогоны, уникальные пользователи, доля успеха, минуты аудио и обработки,
      минут на пользователя, разбивка по тарифам и причинам отказов;
      `recent` — последние прогоны для отладки
- [x] **GPU-утилизация** (главный рычаг маржи) — коэффициент «секунд обработки
      на секунду аудио» (`realtime_factor`): из него считается себестоимость
      минуты и проверяется, сходится ли юнит-экономика
- [x] **Минут на пользователя** — для калибровки лимитов и цен
- [x] **Приватность по умолчанию** — ни аудио, ни текста, ни ключа: ключ и
      устройство только хешем. Уникальных считать можно, восстановить — нет
- [ ] **Конверсия Demo → Standard** — данные уже есть (разбивка по тарифам +
      `http_402` у demo), нужен отдельный отчёт
- [ ] **Churn по тарифам** — нужен срез по датам окончания лицензий
- [ ] **WER на реальных роликах** — качество = удержание (общий инструмент с
      [04-asr-quality](04-asr-quality.md))
- [ ] (позже) Дашборд/выгрузка вместо ручных срезов
- [x] Dep-free тест: `test_events.py`

## Definition of Done

- Ключевые метрики (GPU-утилизация, минут/юзер, конверсия, churn, WER) собираются и доступны для регулярного просмотра.
- По метрикам можно принять решение о цене/лимите/приоритете (данные, а не догадки).

## Заметки
