# Архитектура NP SUB

## Обзор

Два компонента: **панель в Premiere** (клиент) и **API транскрибации** (сервер).
Тяжёлые вычисления (ASR) — только на сервере, клиент лёгкий.

```
Premiere Pro
  └── CEP-панель (index.html + main.js + host.jsx)
        │  1. host.jsx: exportAsMediaDirect → WAV активной секвенции
        │  2. main.js: multipart POST аудио → API
        ▼
NP SUB API (FastAPI)
        │  3. licenses.py: проверка лицензии (ключ/статус/срок/лимит минут)
        │  4. transcribe.py: faster-whisper (kk) → сегменты + пословные тайм-коды
        │  5. segmentation.py: нарезка в аккуратные реплики (длина/время/паузы)
        │  6. srt.py: сегменты → .srt
        ▼
Premiere Pro
        │  6. main.js: пишет .srt во временный файл
        │  7. host.jsx: importFiles(.srt) → ассет субтитров в проекте
        ▼
      Пользователь перетаскивает субтитры на таймлайн
```

## Почему так

| Решение | Причина |
|---|---|
| **ASR на сервере, не в плагине** | модель `large-v3` весит ГБ и требует GPU; нельзя грузить в каждую установку Premiere. Плюс: контроль версий модели, квоты, защита от копирования. |
| **CEP, не UXP** | UXP для Premiere незрелый; CEP даёт стабильный доступ к секвенциям и импорту субтитров. |
| **Формат обмена — `.srt`** | Premiere импортирует SRT как нативные субтитры; не нужно изобретать формат. |
| **Язык зафиксирован `kk`** | авто-детект Whisper путает казахский с русским/татарским/киргизским; фиксация повышает точность. |

## Ключевой технический риск: качество распознавания казахского

Это **сердце продукта**. Whisper `large-v3` понимает казахский, но WER (word
error rate) заметно выше, чем для «крупных» языков. План повышения качества
(по возрастанию усилий):

1. **Baseline** — `large-v3` как есть + VAD + фиксация языка. (сделано)
2. **Постобработка** — казахский спелл-чекер/нормализация, восстановление
   пунктуации, словарь частых терминов.
3. **Fine-tuning** — дообучение на **Kazakh Speech Corpus (KSC2, ISSAI)** —
   ~1000+ часов размеченной казахской речи. Это главный технический моут:
   даёт качество, которого нет у «универсальных» решений.
4. **Специализированные модели** — сравнить с ISSAI Soyle / Yandex SpeechKit
   (kk-KZ) как альтернативным или резервным движком.

## Масштабирование (когда пойдут пользователи)

Текущий MVP — синхронный: запрос держит соединение до конца транскрибации.
Для нагрузки:
- **Очередь задач** (Redis/RQ или Celery): панель отправляет аудио → получает
  `job_id` → опрашивает `/jobs/{id}`.
- **Пул GPU-воркеров**, автоскейл по длине очереди.
- **Объектное хранилище** для аудио вместо диска.
- **CDN/пресайн-URL** для загрузки больших файлов напрямую в хранилище.

## Безопасность и приватность

- Аудио — контент пользователя. Удалять сразу после обработки (сейчас: temp-файл
  чистится в `finally`). Не логировать содержимое.
- HTTPS обязателен на проде (ключи и аудио идут по сети).
- Ключи хранить хэшированными; ротация; rate-limit по IP/ключу.
