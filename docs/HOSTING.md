# Хостинг KZ-SUB (чтобы плагином могли пользоваться все)

«Дать доступ всем» = **две независимые задачи**:

1. **Поднять бэкенд** на публичном HTTPS-адресе (эта страница).
2. **Раздать плагин** — подписать `.zxp` и выложить на Adobe Exchange
   (см. раздел «Дистрибуция плагина» ниже).

---

## Главное ограничение: `large-v3` хочет GPU

На CPU `large-v3` работает медленно (медленнее реального времени) — для одного
пользователя терпимо, для публичного сервиса нет. Поэтому для хостинга нужен
**GPU** (или managed-ASR, но ты выбрал Whisper за качество).

## Варианты хостинга

| Вариант | Плюсы | Минусы | Когда |
|---|---|---|---|
| **Serverless GPU** (Runpod Serverless, Modal, Replicate) | платишь только за секунды обработки, **масштаб до нуля** — нет платы за простой | чуть больше настройки, «холодный старт» на первый запрос | **старт / низкий и рваный трафик** ← рекомендую |
| **GPU-VPS/инстанс** (аренда карты T4/A10) | самая низкая цена за минуту при высокой загрузке, полный контроль | платишь за простой 24/7, сам админишь | когда поток стабильный и большой |
| **Managed ASR API** (Yandex SpeechKit kk-KZ и т.п.) | без GPU и без ops | зависимость от вендора, платишь за минуту, не твой Whisper | как запасной движок |

**Рекомендация на запуск:** serverless-GPU (Runpod/Modal). Пока пользователей
мало — платишь копейки (только за реальную транскрибацию), при росте — переезд
на выделенный GPU, когда утилизация оправдает постоянную аренду.

## Деплой контейнера (общая схема, подходит любому провайдеру)

Бэкенд уже контейнеризован: `backend/Dockerfile` (CPU) и `backend/Dockerfile.gpu`.

```bash
# GPU-образ
docker build -f backend/Dockerfile.gpu -t kzsub-api:gpu backend

# Локальный прогон на GPU-хосте
docker run --gpus all -p 8000:8000 \
  -e KZSUB_API_KEYS="секрет-1:pro,триал:free" \
  -v hfcache:/root/.cache/huggingface \
  kzsub-api:gpu
```

Дальше — залить образ в реестр провайдера и запустить его сервисом. У Runpod/
Modal есть деплой прямо из образа или из репозитория.

### Что ОБЯЗАТЕЛЬНО настроить перед публичным доступом
- **`KZSUB_API_KEYS`** — свои секретные ключи. Иначе работает общеизвестный
  `dev-key`, и любой получит бесплатный безлимит.
- **HTTPS** — панель шлёт аудио и ключ по сети. Поставь сервис за TLS
  (у serverless-провайдеров HTTPS из коробки; на своём VPS — Caddy/nginx).
- **Том для весов** (`/root/.cache/huggingface`) — чтобы `large-v3` (~3 ГБ) не
  качался при каждом старте.

### CORS не нужен
Панель ходит на сервер через Node-`http` (не браузерный `fetch`), поэтому
CORS-настройка не требуется.

## Что доделать до реальных продаж (сейчас заглушки)
Это уже не про «поднять», а про «продавать» — но важно помнить:
- **Учёт квоты — в памяти процесса** (`quota.py`). При нескольких репликах или
  рестарте счётчик сбрасывается. Для биллинга нужна **общая БД** (Postgres/Redis).
- **Аутентификация — статичные ключи** из env. Для самообслуживания нужны
  регистрация и генерация ключей на сайте + оплата (Kaspi/Stripe).

Рекомендуемый порядок: сначала поднять бэкенд на serverless-GPU с секретными
ключами (раздаёшь ключи вручную первым пользователям/бете), потом — БД+оплата.

## Направить панель на прод-сервер
В панели поле **API URL** — вписать публичный `https://…`-адрес; значение
запоминается. Для массовой раздачи можно зашить прод-URL как значение по
умолчанию в `plugin/index.html` (поле `#apiUrl`).

## Дистрибуция плагина (вторая половина задачи)
Чтобы пользователи ставили панель без dev-режима CEP:
1. **Подписать `.zxp`** утилитой `ZXPSignCmd` (нужен сертификат подписи).
2. Выложить на **Adobe Exchange** (модерация Adobe) и/или дать `.zxp` +
   установщик (например, ZXP/UXP Installer) для прямой установки.

Подробные шаги подписи вынесем отдельно, когда бэкенд будет на проде.
