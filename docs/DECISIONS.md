# DECISIONS — журнал архитектурных решений (ADR)

Короткие записи «что решили и почему», чтобы не переспоривать одно и то же и не
ломать осознанные компромиссы. Новое решение — новая запись внизу (не редактируй
старые; если решение отменено — добавь запись «Заменяет ADR-N»).

Формат: **Контекст → Решение → Почему → Компромиссы.**

---

## ADR-1. Тонкий клиент, тяжёлое — на сервере
- **Контекст:** ASR-модель весит гигабайты и требует GPU.
- **Решение:** транскрибация только на бэкенде; панель лишь оркестрирует и
  показывает результат.
- **Почему:** нельзя грузить модель в каждую установку Premiere; централизация
  даёт контроль версий модели, квоты и защиту ноу-хау.
- **Компромиссы:** нужен онлайн и работающий сервер; появляется сетевая задержка.

## ADR-2. Прокси-режим: шлюз → Runpod (а не Whisper на Fly)
- **Контекст:** нужен публичный HTTPS-эндпоинт, но GPU дорогой и не нужен 24/7.
- **Решение:** лёгкий FastAPI-шлюз на CPU (Fly) проксирует тяжёлую работу в
  Runpod Serverless GPU. Один `main.py` умеет оба режима (локальный/прокси).
- **Почему:** ключи и квоты остаются на нашем шлюзе (не утекают в панель); GPU
  платится только за секунды обработки.
- **Компромиссы:** двойной сетевой хоп; шлюз держит соединение, пока Runpod считает.

## ADR-3. Serverless-GPU (Runpod), а не постоянный GPU-инстанс
- **Контекст:** на старте трафик редкий и рваный.
- **Решение:** Runpod Serverless со scale-to-zero.
- **Почему:** за простой платишь $0; идеально для низкого/пикового трафика.
- **Компромиссы:** «холодный старт» первого запроса (mitigation: FlashBoot, idle
  timeout, сетевой том с весами, подсказки терпения в UI). Пересмотреть при
  стабильно высоком трафике.

## ADR-4. CEP, а не UXP для панели
- **Контекст:** у Adobe два API расширений; UXP — новее.
- **Решение:** CEP (HTML/JS + ExtendScript).
- **Почему:** для Premiere UXP на момент старта незрелый; CEP даёт полный доступ к
  секвенциям, экспорту аудио и `createCaptionTrack`.
- **Компромиссы:** старый движок CEF (ES5, никаких сборщиков); Adobe когда-нибудь
  задепрекейтит CEP — миграция на UXP в роадмапе.

## ADR-5. Анти-шаринг: привязка к устройству, не к IP
- **Контекст:** нельзя, чтобы один купленный ключ гулял по рукам.
- **Решение:** панель шлёт `X-Device-Id` (хэш от hostname+user+platform); ключ
  работает на N устройствах (`KZSUB_MAX_DEVICES_PER_KEY`, дефолт 2).
- **Почему:** IP у людей постоянно меняется (ломает честных) и делится за NAT
  (не ловит шаринг); VPN обходит IP мгновенно.
- **Компромиссы:** это защита от бытового шаринга, не абсолютная; главный
  ограничитель расходов — серверные квоты.

## ADR-6. Аудио-пресет 16 kHz mono
- **Контекст:** экспорт секвенции требует `.epr`-пресета; размер аудио важен для
  лимита запроса Runpod и длинных видео.
- **Решение:** вшитый пресет 16 kHz, моно.
- **Почему:** Whisper всё равно работает на 16 kHz mono — качество не страдает, а
  файл в ~6 раз меньше 48 kHz стерео.
- **Компромиссы:** нет (для ASR это оптимум).

## ADR-7. Веса модели: из образа → на Network Volume
- **Контекст:** веса, вшитые в Docker-образ, раздували его до ~8 ГБ → медленный
  холодный пулл на каждом новом воркере (наблюдались зависания на 10+ минут).
- **Решение:** слим-образ + модель на сетевом томе Runpod (кэш HF на томе).
- **Почему:** образ выкачивается за минуту; модель качается один раз и
  переиспользуется всеми воркерами.
- **Компромиссы:** сетевой том привязан к одному дата-центру → зависимость от его
  доступности GPU (в регионах с `Low Supply` это риск; выбирать ДЦ с хорошим
  запасом). Альтернатива при проблемах ДЦ — оставаться на FlashBoot без тома.

## ADR-8. Двуязычные тексты UI через невидимый разделитель
- **Контекст:** сообщения нужно показывать каз, затем рус (по кругу).
- **Решение:** строки вида `«каз<SEP>рус»` (SEP = `␟`), `setStatus` крутит
  языки; ошибки несут перевод через `biErr()`.
- **Почему:** не тащить i18n-фреймворк в простую панель; перевод живёт рядом с
  сообщением.
- **Компромиссы:** ручной перевод каждой строки; следи, чтобы SEP не попал в текст.

## ADR-9. Внутреннее имя `kzsub` сохраняем, продукт — «NP SUB»
- **Контекст:** продукт переименован в NP SUB, но всё внутри — `kzsub`.
- **Решение:** переименовываем только пользовательское (UI, заголовки доков, файл
  `NP-SUB.zxp`); `KZSUB_`, `kzsub-gateway`, `kzsub-runpod`, `kz.kzsub.panel`,
  `kzsub_data` — оставляем.
- **Почему:** внутренние идентификаторы невидимы пользователю, а их переименование
  ломает деплой (Fly-приложение, образ, том, bundle id) без выгоды.
- **Компромиссы:** лёгкое расхождение имён в коде vs продукте — задокументировано.

## ADR-11. Веса — обратно в образ; мульти-ДЦ вместо Network Volume (заменяет ADR-7)
- **Контекст:** ADR-7 предлагал вынести веса на Network Volume ради быстрых
  холодных стартов. Но на практике у Runpod том **жёстко привязан к одному
  дата-центру**, а в дефицитных регионах (наблюдали Исландию с `Low Supply`) это
  запирает эндпоинт в нехватке GPU. Том так и не был задеплоен.
- **Решение:** веса **запекаем в образ** (как в ADR-7 «до»), тома не используем.
  Эндпоинту разрешаем **несколько дата-центров** — Runpod берёт GPU там, где есть
  свободная карта. На эндпоинте: **Container Disk ≥ 30 GB** и **FlashBoot ON**.
- **Почему:** доступность GPU важнее скорости первого старта для продукта на
  старте («работает, когда юзер нажал» > «стартует на 30с быстрее»). FlashBoot
  кэширует образ у Runpod → повторные холодные старты быстрые; редкий медленный
  первый пулл смягчён подсказками терпения в UI.
- **Компромиссы:** образ толстый (~8 ГБ), первый пулл на новом хосте — минуты
  (разово). Если в будущем трафик станет высоким и сконцентрированным в одном
  регионе с хорошим запасом GPU — можно вернуться к тому (ADR-7).

## ADR-10. Караоке-нарезка «одно слово на реплику» по умолчанию
- **Контекст:** аудитория — авторы Shorts/Reels/TikTok.
- **Решение:** `CAPTION_STYLE=word` по умолчанию; короткие предлоги/частицы
  прилипают к следующему слову; пунктуация убирается (кроме `!`), опц. капс.
- **Почему:** это доминирующий стиль субтитров в вертикальных видео.
- **Компромиссы:** для «классических» субтитров есть режим `phrase` (env-переключатель).
